# EF Core Migrations

The baseline migration `20260131000000_Initial` ships in source control so every environment
deploys the identical schema. The generated `.Designer.cs` + `ModelSnapshot` pair is intentionally
not committed because it is regenerated by the tooling; when you add a new migration, run:

```bash
dotnet ef migrations add <Name> \
  --project src/FinTrack.Infrastructure \
  --startup-project src/FinTrack.Api
```

The tool re-creates the snapshot from the current model (`FinTrackEntityConfigurations`), which is
the single source of truth. `DatabaseInitializer` applies pending migrations on API startup, and CI
runs `dotnet ef migrations has-pending-model-changes` to fail fast on model/migration drift.

Critical objects managed *outside* EF Core migrations live in `database/scripts/*.sql`
(stored procedures + the indexed view) — see `docs/database.md` for the rationale.
